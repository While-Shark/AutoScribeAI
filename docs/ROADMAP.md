# AutoScribeAI 开发任务清单

更新：2026-09-29。M0 已实现；M1 的候选清单和覆盖报告已实现，真实浏览器探索待推进。

用户已授权开始开发，当前完成首批 M0 工作。本清单中的阶段、技术细节和拆分是建议安排，可在首次实现验证后调整。

## 里程碑与依赖

| 阶段 | 交付目标 | 依赖 |
| --- | --- | --- |
| M0：输入与运行约定 | 可校验的输入、内容模型、状态文件、能力检测 | 开发启动 |
| M1：发现与探索 | 可追溯的模块地图、操作流程和真实截图 | M0 |
| M2：图文 HTML | 根据证据生成离线可读手册 | M1 |
| M3：多格式交付 | DOCX、Markdown 与 HTML 下载入口 | M2 |
| M4：首版验收 | 安装使用说明、示例、恢复验证及质量报告 | M3 |
| 后续增强 | 增量更新、多角色、更多宿主与软件类型 | M4 |

首个可用版本包含 M0–M4；HTML、Word 和 Markdown 均属于首版目标。PDF 等增强不阻塞首版。

## M0：输入、模型与运行骨架（P0）

- [x] T01 定义项目配置：源码/URL、角色、范围、语言、输出格式、允许动作及测试数据规则。
- [x] T02 建立 Project、Module、Feature、Workflow、Step、Evidence、Manual 的结构约定与校验规则；包含 schemaVersion 和稳定 ID。
- [x] T03 定义 manifest、checkpoint 和阶段状态；实现原子保存和基本恢复。
- [x] T04 建立宿主能力探测：浏览器、终端、文件、文档导出，明确缺失工具时的输出和降级。
- [x] T05 编写五个 Skill 的职责、输入输出和入口编排，避免互相重复执行。

验收：有效配置可进入执行计划；无效输入给出清晰原因；缺少浏览器时明确无法验证界面；敏感凭据不落盘到配置；中断后能够恢复到正确阶段。

## M1：项目分析与真实探索（P0）

- [ ] T06 从源码/已有说明发现菜单、路由、模块、角色和候选流程；记录来源。
- [ ] T07 从在线项目收集可见菜单与页面，与源码分析结果对照。
- [x] T08 生成模块—功能—角色—流程覆盖矩阵，定义每条流程的完成标准。
- [ ] T09 设计动作执行、页面稳定检查、结果观察、超时重试与阻塞处理。
- [ ] T10 按流程采集关键截图，保存步骤、实际结果与证据的关联。
- [ ] T11 实现截图裁剪、编号/箭头和脱敏处理，验证缩放后的标注位置。
- [ ] T12 处理登录接管、权限不足、数据缺失及有副作用动作；恢复时防止重复提交。

依赖：T06/T07 基于 T01/T04；T08 汇总分析结果；T09/T10 依赖 T02/T08；T11 基于截图证据；T12 贯穿探索和恢复。

验收：选一个小型测试项目，至少覆盖两个模块和三条代表性流程，包含一个结果状态和一个受控阻塞场景。每条已验证流程都有真实证据；未验证项保留原因，不伪造操作结果。

## M2：统一手册与 HTML（P0）

- [ ] T13 将已采集证据转换为 manual.json，校验所有步骤和图片引用。
- [ ] T14 建立章节规范：模块用途、适用角色、前置条件、操作步骤、预期结果、必要的常见问题。
- [ ] T15 生成 HTML，支持目录、搜索、图片放大、响应式阅读和项目版本说明。
- [ ] T16 组织相对路径静态资源，支持完整目录包离线阅读。
- [ ] T17 在手册中呈现覆盖范围、未验证项与阻塞原因，并生成机器可读质量报告。

验收：不接网络也能阅读完整手册；图片、目录和搜索可用；说明与截图一致；正文清楚区分已验证内容与推断；输出不依赖常驻服务。

## M3：Word 与 Markdown 导出（P0）

- [ ] T18 从统一模型生成 DOCX，支持标题、步骤、截图、图注、页码和分页规则。
- [ ] T19 从统一模型生成 Markdown 及配套 assets，打包为可移动的 ZIP。
- [ ] T20 在 HTML 中提供预生成 DOCX 和 Markdown 包的下载入口。
- [ ] T21 检查三种格式的章节、步骤和图片一致性；对 DOCX 渲染做视觉检查并修复排版。

验收：DOCX 图片全部内嵌，中文可读，无明显截断/遮挡；Markdown 解压并移动目录后图片可用；HTML 中下载到的是有效文件；三种格式不存在缺章或步骤丢失。

### M0 实现记录

- Python CLI：配置/手册校验、init、status、stage、resume。
- schemas：项目配置、统一内容与证据、宿主声明、manifest、checkpoint。
- 运行状态：本地单写锁、原子替换、checkpoint 修复、版本/范围变化检测、中断阶段阻塞，绝不自动重放浏览器动作。
- 能力预检：文件写入与源码目录检查；浏览器使用宿主声明，缺失时明确降级；导出依赖存在不等于导出器已实现。
- 五个 Skill：已建立入口与交接规范，当前采用完整仓库引用方式；不是独立安装包。
- 测试覆盖配置/敏感信息、状态转移/中断、路径逃逸、引用关系与证据摘要。T24 仅部分落实，完整导出及步骤级防重复仍待后续。
- 限制：阶段完成由调用者声明；T06 当前通过 AI 产出的项目清单输入完成静态信息建模，没有自动解析任意框架路由的适配器；T07 在线菜单收集与真实截图尚未实现。HTML、Word、Markdown 导出也未完成。
