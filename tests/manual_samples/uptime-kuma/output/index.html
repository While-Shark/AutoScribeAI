HTTP 监控

入口: src/pages/EditMonitor.vue · 来源: 源码说明

创建 HTTP 监控并设置检查参数 已验证

流程位置: src/pages/EditMonitor.vue
适用角色与前置条件

角色: user

  • 已打开 Uptime Kuma 的 Web 界面并具有添加监控项的权限。
  1. 进入“添加监控项”，选择 HTTP(s) 类型。
    操作位置: src/pages/EditMonitor.vue
    预期: 添加监控项表单显示 HTTP(s) 类型及名称、URL、检查间隔等配置项。
    实际: 添加监控项表单显示 HTTP(s) 类型及名称、URL、检查间隔等配置项。
  2. 填写名称 AutoScribe Demo Website 和 URL https://example.com，保留 60 秒检查间隔。
    操作位置: src/pages/EditMonitor.vue
    预期: 表单使用合成名称与 example.com；保存后的监控详情显示该 URL 和 60 秒检查间隔。
    实际: 表单使用合成名称与 example.com；保存后的监控详情显示该 URL 和 60 秒检查间隔。
  3. 保存监控，并在仪表盘和心跳历史中核对状态。
    操作位置: src/pages/EditMonitor.vue
    预期: 仪表盘出现 AutoScribe Demo Website；首次及后续心跳均为 HTTP 200 - OK，状态正常。
    实际: 仪表盘出现 AutoScribe Demo Website；首次及后续心跳均为 HTTP 200 - OK，状态正常。

配置通知渠道用于接收告警 已验证

角色: user

  • 已准备通知服务所需的非敏感连接信息。
  1. 在“设置 → 通知”中打开新增通知渠道，选择 Webhook。
    操作位置: src/components/notifications
    预期: 通知类型列表包含 Webhook，切换后显示 Post URL、HTTP 方法和请求体字段。
    实际: 通知类型列表包含 Webhook，切换后显示 Post URL、HTTP 方法和请求体字段。
  2. 填入 Demo Placeholder Webhook 与 https://example.invalid/uptime-kuma-test，并选择 application/json 请求体。
    操作位置: src/components/notifications
    预期: 渠道保存成功，通知列表出现 Demo Placeholder Webhook。未点击“测试”，未发送通知。
    实际: 渠道保存成功，通知列表出现 Demo Placeholder Webhook。未点击“测试”，未发送通知。
  3. 编辑 AutoScribe Demo Website，勾选 Demo Placeholder Webhook 并保存。
    操作位置: src/components/notifications
    预期: 监控编辑页中 Demo Placeholder Webhook 复选框已勾选，页面提示已保存。
    实际: 监控编辑页中 Demo Placeholder Webhook 复选框已勾选，页面提示已保存。
